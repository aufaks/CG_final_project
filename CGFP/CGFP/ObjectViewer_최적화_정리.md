# ObjectViewer 로딩 최적화

> 수정 파일: `CGFP/CGFP/ObjectViewer.cpp` 하나
> 게임 프로젝트(`CGFP`), `.vcxproj`, 셰이더, 에셋은 건드리지 않음

## 요약

- **첫 화면:** Debug 약 20초 → **0.4초**, Release 약 8초 → **0.4초**
- **Krusty Krab(정점 52만) 로딩:** Release 4.9초 → **약 0.35초** (두 번째 실행부터, 캐시 사용)
- 모델을 불러오는 동안에도 창이 멈추지 않고, ←/→가 대부분 바로 바뀜
- 렌더링 결과(모양, 텍스처 픽셀)는 수정 전과 완전히 같음

## 바뀐 점

### 1. 필요할 때만 불러오기
- 원래는 시작할 때 모델 10개를 전부 불러온 뒤에야 창을 띄웠음.
- 지금은 보는 모델만 불러오고, 다음·이전 모델은 백그라운드에서 미리 불러 둠.

### 2. 로딩 스레드 분리
- 파싱, 텍스처 디코딩, GPU 업로드를 별도 스레드에서 함.
- GPU 업로드는 숨겨진 창의 **공유 OpenGL 컨텍스트**에서 하고, 메인 스레드는 VAO만 만듦. VAO는 컨텍스트끼리 공유가 안 되기 때문.
- 불러오는 동안 이전 모델이 계속 보이고, 창 제목에 `불러오는 중: 파일명`이 표시됨.
- 공유 컨텍스트를 만들지 못하면 메인 스레드에서 업로드함.

### 3. OBJ 파서 재작성
| 원래 | 바꾼 것 |
|---|---|
| `getline`으로 한 줄씩 읽음 | 파일 전체를 한 번에 읽고 포인터로 줄을 나눔 |
| 줄마다 `istringstream` + `>>` | `std::from_chars`로 숫자 변환 |
| 면(`f`)마다 `vector`/`string`/`substr` 할당 | 벡터 하나를 재사용하고 문자열은 포인터 범위로만 다룸 |
| 정점마다 재질 이름으로 해시 조회 | `usemtl`이 바뀔 때만 조회 |

그대로 둔 동작: 음수 인덱스, 0/범위 밖 인덱스 에러 메시지, `vn` 정규화, fan 삼각분할, 노멀 없을 때 면 노멀, `mtllib`/`usemtl` 이름 Trim, 4번째 이후 `/` 파트 무시.

### 4. 텍스처 병렬 디코딩
- MTL을 먼저 읽어서, OBJ를 파싱하는 동안 PNG를 여러 스레드로 동시에 디코딩함.
- 위아래 뒤집기는 WIC(`IWICBitmapFlipRotator`)가 디코딩하면서 처리해서 복사를 한 번 줄임.

### 5. 파싱 결과 캐시
- 위치: `%LOCALAPPDATA%\CGFP-ObjectViewer\cache\*.ovcache` (저장소 밖이라 git과 상관없음)
- OBJ의 크기나 수정 시간이 바뀌면 자동으로 다시 파싱함.
- 캐시를 지우려면 위 폴더를 삭제하면 됨.
- 파싱 규칙(크기 조정, 카메라 시작 위치 등)을 바꾸면 코드의 `kCacheVersion`을 올려야 예전 캐시가 무시됨.

### 6. 인덱스 버퍼(EBO)
- 같은 정점을 한 번만 저장하고 `glDrawElements`로 그림.
- Krusty Krab: 정점 521,277개 → 157,576개, GPU 메모리 약 16.7MB → 약 7MB.

### 7. 기타
- uniform 위치를 시작할 때 한 번만 찾음 (예전엔 매 프레임 `glGetUniformLocation`을 호출)
- `Windows.h`를 GL 헤더보다 먼저 include해서 원래 나던 `APIENTRY` 재정의 경고(C4005)를 없앰
- 로딩에 실패한 모델은 예전처럼 `Skipped:`를 출력하고 목록에서 빠지며, 누르던 방향의 다음 모델로 넘어감
- 로그 형식: `Loaded: 경로 (그린 정점 수, 고유 정점 수, 걸린 ms, cache)`

## 알아 둘 점

- 처음 불러올 때는 고유 정점을 찾는 작업이 추가돼 Debug에서 Krusty Krab이 약 0.4초 더 걸림. 캐시가 생긴 뒤부터는 빠름.
- 모델 하나를 불러오는 동안 CPU 코어를 여러 개 씀.
- 나중에 게임 본체(`main.cpp`)에서 OBJ를 불러오게 되면 이 로더를 그대로 옮겨 쓸 수 있음.
